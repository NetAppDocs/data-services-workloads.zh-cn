= 使用 NetApp Workload Factory for Databases 保护 Microsoft SQL Server 工作负载
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
从 Workload Factory 控制台使用 NetApp Backup and Recovery 保护您的 Microsoft SQL Server 应用程序数据。通过此集成，您可以实现以下保护目标：使用本地主 Amazon FSx for NetApp ONTAP（FSx for ONTAP）存储上的本地快照备份工作负载，并将工作负载复制到辅助 FSx for ONTAP 存储。



[[about-this-task]]
== 关于此任务

Workload Factory 可自动发现资源、验证先决条件，以及配置和安装 Microsoft SQL Server 插件，以为使用 NetApp Backup and Recovery 保护您的工作负载做好准备。该插件是 NetApp 软件的主机端组件，使您能够保护 Microsoft SQL Server 工作负载。

NetApp Backup and Recovery 利用 NetApp SnapMirror 数据复制技术，通过创建快照副本并将其传输到备份位置，确保所有备份完全同步。

有关使用 Backup and Recovery 进行保护的详细信息，请参阅 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["使用备份和恢复保护 Microsoft SQL 工作负载概述"^]。



[[before-you-begin]]
== 开始之前

必须满足以下要求才能使用备份和恢复保护 Microsoft SQL Server 工作负载。

* 确保您的环境符合 link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#microsoft-sql-server-workload-requirements["备份和恢复 SQL Server 要求"^]。
* link:https://docs.netapp.com/us-en/data-services-backup-recovery/concept-start-prereq.html#in-netapp-console["完成 NetApp Console 要求"^] 包括设置、分配 IAM 角色和安装 Console 代理。


如果您具有 NetApp 账户的组织管理员访问权限，则当您<<为使用 NetApp Backup and Recovery 进行保护做好准备,使用 NetApp Backup and Recovery 为保护做好准备>>时，系统将自动为您分配 `backup and recovery super admin`角色。

* 在 Connector 上设置主机解析
+
要发现数据库，必须在 Connector 上设置主机解析。在托管设备上，在  `/etc/hosts` 文件中添加 IP 地址到主机名的映射。

+
** link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-licensing.html["设置 NetApp Backup and Recovery 的许可"^]






[[prepare-for-protection-with-netapp-backup-and-recovery]]
== 为使用 NetApp Backup and Recovery 进行保护做好准备

完成准备过程，以使用 NetApp Backup and Recovery 保护您的 Microsoft SQL Server 资源。

.步骤
. 登录到 link:https://console.netapp.com["NetApp Console"^]。
. 选择菜单 image:workloads-menu-icon.png["汉堡菜单图标用于导航到 Workloads，即 Workload Factory 的菜单项"]，*Workloads* > *Databases*。
. 从“数据库”菜单中，选择 *清单*。
. 在清单中，选择 *Microsoft SQL Server* 作为引擎类型。
. 找到要保护的实例，然后从菜单中选择*保护*。
. 如果出现提示，请提供具有管理访问权限的 Windows 凭据。
+
若要使用 NetApp Backup and Recovery 进行保护，必须使用 Windows 凭据在 Workload Factory 中注册 SQL Server 实例。

. 如果多个 Console 代理处于活动状态且可用，请选择要注册和保护工作负载的 *Console 代理*。
. 为了准备数据保护，Workload Factory 会自动在 Backup and Recovery 中注册您的 SQL Server 资源，配置并安装 Microsoft SQL Server 插件，并发现资源以满足保护 SQL Server 实例的先决条件。选择 *开始* 以开始此过程。
. 满足前提条件后，选择*重定向*访问备份和恢复。


.下一步
从 Backup and Recovery 中，创建策略以保护您的 Microsoft SQL Server 实例和数据库。

link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-policies-create.html["了解如何创建策略以保护 Microsoft SQL Server 实例和数据库"^]。

有关相关信息，请参阅link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-mssql-protect-overview.html["备份和恢复文档"^]以管理 Microsoft SQL Server 工作负载。



[[edit-protection-for-microsoft-sql-server-resources]]
== 编辑对 Microsoft SQL Server 资源的保护

您可以编辑在 NetApp Backup and Recovery 中已受保护的 Microsoft SQL Server 实例和数据库的保护。通过编辑保护，您可以修改受保护的 SQL Server 实例的保护策略或计划。

.步骤
. 登录到 link:https://console.netapp.com["NetApp Console"^]。
. 选择菜单 image:workloads-menu-icon.png["汉堡菜单图标用于导航到 Workloads，即 Workload Factory 的菜单项"]，*Workloads* > *Databases*。
. 从“数据库”菜单中，选择 *清单*。
. 在清单中，选择 *Microsoft SQL Server* 作为引擎类型。
. 选择
. 找到要编辑保护的数据库，然后从菜单中选择*编辑保护*。
+
您将被重定向到 NetApp Console 中的备份和恢复，您可以在其中修改保护策略或计划。
