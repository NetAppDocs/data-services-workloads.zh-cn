= 探索 NetApp Workload Factory for Databases 中的节省
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
通过比较在 Amazon Elastic Block Store (EBS)、FSx for Windows File Server 和内部存储上使用 Microsoft SQL Server 与使用 FSx for ONTAP 存储的成本，在 NetApp Workload Factory for Databases 中探索您的数据库工作负载的节省情况。



[[about-this-task]]
== 关于此任务

您可以使用仪表板、库存选项卡或浏览节省选项卡来探索数据库工作负载在 EBS、FSx for Windows File Server 和本地存储上的节省。在所有情况下，您可以使用节省计算器来比较在 FSx for ONTAP 文件系统上运行 Microsoft SQL Server 工作负载与 Elastic Block Store (EBS)、FSx for Windows File Server 和本地存储相比的各种成本组件，如存储、计算、SQL 许可证、快照和克隆。

如果 Workload Factory 发现 FSx for ONTAP 节省了成本，则可以直接从 Workload Factory 控制台中的节省计算器部署 Microsoft SQL over FSx for ONTAP。当 Elastic Block Store、FSx for Windows File Server 或本地存储上有多个 Microsoft SQL Server 实例时，我们建议使用单个 SQL 实例的 FSx for ONTAP 配置。

.所有数据库工作负载的潜在节省
访问 Workload Factory 控制台中的数据库*仪表板*，了解在 FSx for ONTAP 上运行所有数据库工作负载的潜在成本节省概览。*潜在节省*图块显示了 EBS 和 FSx for Windows File Server 上的数据库工作负载、潜在成本节省、节省百分比和条形图。

image:screenshot-dashboard-potential-savings-tile.png["Workload Factory 控制台中数据库仪表板的潜在节省图块的屏幕截图。潜在节省图块显示了您在 Elastic Block Store 和 FSx for Windows File Server 上的所有数据库工作负载的数量、潜在成本节省、节省百分比以及条形图中的可视化表示。"]

.节省计算器
您可以使用节省计算器，以便将运行 Microsoft SQL Server 工作负载（如存储、计算、SQL 许可证、快照和克隆）在 FSx for ONTAP 文件系统上的数据库工作负载的各种成本成分与 Elastic Block Store (EBS)、FSx for Windows File Server 和本地存储进行比较。FSx for ONTAP 文件系统可能是数据库工作负载的最具成本效益的选择。

计算器显示如果使用 FSx for ONTAP 文件系统，这些 Microsoft SQL Server 上数据库工作负载的存储成本是否会更低。 <<计算器选项,了解如何使用计算器。>>

image:screenshot-ebs-savings-calculator-update.png["节省计算器页面的屏幕截图在左侧显示了所选的 Amazon Elastic Block Store 上的 Microsoft SQL Server 配置，并提供了自定义快照和克隆值的选项。左侧显示了以美元金额和百分比表示的成本节省，以及在 FSx for ONTAP 和 Elastic Block Store 存储上使用 Microsoft SQL Server 的每月总成本。"]



[[sql-server-deployment-analysis]]
== SQL Server 部署分析

计算器会检查 SQL Server 部署，以确保使用的资源和功能与 SQL Server 版本相匹配。以下是计算器在建议降级到标准版之前检查的关键因素和条件：

.部署模式
计算器评估部署模型以及是否需要企业版。

.已分配资源
计算器评估以下依赖于许可证的分配资源的条件：

* 目标实例 vCPU：实例具有 48 个或更少的虚拟 CPU。
* 内存分配：实例的内存为 128GB 或更少。


.企业版功能使用情况
计算器将验证是否正在使用以下任一 Enterprise 功能：

* 数据库级 Enterprise 功能
* 联机索引操作
* 资源管理器
* 对等或 Oracle 复制
* R/Python 扩展
* 内存优化的 TempDB


如果评估的 SQL Server 实例未使用上述任何 Enterprise 功能并满足资源限制，则计算器将建议将许可证降级到 Standard Edition。计算器可帮助您在不降低性能或功能的情况下优化 SQL Server 许可成本。



[[calculator-options]]
== 计算器选项

有两个计算器选项可用于在您的系统和 FSx for ONTAP 之间进行成本比较——自定义和检测。

通过自定义探索节省费用：您提供 Amazon EC2 上带有 EBS 或 FSx for Windows File Server 的 Microsoft SQL Server 的配置设置，包括区域、部署模型、SQL Server 版本、每月数据更改率、快照频率等。

探索检测到的主机的节省：Workload Factory 链接到您现有的 Microsoft SQL 服务器，并将详细信息提取到计算器中以进行自动比较。您需要授予 _查看、规划和分析_ 权限才能使用此计算器选项。您可以更改用例，但所有其他详细信息将在计算中自动确定。

此外，您可以 link:../fsx-storage/add-credentials.html["添加 AWS 凭据"^] 以提高计算器分析的准确性。选择 *根据现有资源计算节省金额*。您将被重定向到“添加凭据”页面。添加凭据后，选择要与 FSx for ONTAP 进行比较的现有资源，然后选择 *探索节省金额*。

.. *克隆刷新频率*：从菜单中选择克隆刷新频率。
.. *克隆副本数*：输入本地配置中的克隆副本数。
.. *每月变化率*：输入克隆和快照数据每月平均变化的百分比。


. 要获得更准确的结果，请更新计算信息以及存储和性能详细信息。
+
