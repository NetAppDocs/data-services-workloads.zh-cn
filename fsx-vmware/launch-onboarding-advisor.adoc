= 使用 VMware 工作负载迁移顾问创建 VMware Cloud on AWS 部署计划
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
登录到 NetApp Workload Factory 以访问 VMware 迁移顾问。您将按照向导中的步骤创建根据您的需求定制的部署计划或迁移计划。

迁移到 VMware Cloud 时，您可以使用迁移顾问将当前本地 vSphere 环境迁移到 VMWare cloud。

请注意，您必须拥有用户名和密码才能访问 Workload Factory。如果您没有访问权限，请立即创建账号。查看说明 link:quick-start-vmware.html["此处"]。



[[create-a-deployment-plan-based-on-an-on-premises-vsphere-environment]]
== 基于本地 vSphere 环境创建部署计划

您可以将本地 vSphere 环境中的当前虚拟机配置迁移到 VMware Cloud on AWS 中的虚拟机，并将定制的 Amazon FSx for NetApp ONTAP 文件系统用作外部数据存储。

.要求
* 您必须已使用迁移顾问 VM 收集器（.csv 文件）或使用 RVTools（.xlsx 文件）从现有系统创建了清单文件。
* 您必须能够从登录到 Workload Factory 的系统访问清单文件。


.步骤
. 登录到 link:https://console.netapp.com["NetApp Console"^]。
. 选择菜单 image:workloads-menu-icon.png["汉堡菜单图标用于导航到 Workloads，即 Workload Factory 的菜单项"]，*Workloads* > *VMware*。
+
此时将显示规划中心。

. 选择*计划并创建 VMC*。
. 选择用于将当前虚拟机配置填充到 Workload Factory 中的清单文件类型，然后选择*下一步*。
+
** 选择*使用迁移顾问 VMware 数据收集器*以使用通过 VMware 数据收集器创建的 .csv 文件。
** 选择 *使用 RVTools* 以使用通过 RVTools 创建的 .xlsx 文件。


+
此时将显示“Prepare for VMware Cloud onboarding”页面。

. 在 _上传虚拟机配置_ 部分，选择 image:button-upload-file.png["上传按钮"] 并选择要使用的文件。
+
** 使用 Migration advisor VM collector 时，选择 .csv 文件。
** 使用 RVTools 时选择 .xlsx 文件。


+
虚拟机摘要部分是从清单文件中填充的，以反映虚拟机的数量和总存储容量。

. 在 _VM 库存注意事项_ 部分中，选择用于筛选要迁移的 VM 列表的选项。
+
.. *考虑虚拟机*：指出将根据其运行电源状态从 .csv 文件中提取哪些虚拟机。您可以引入所有虚拟机，或者仅引入处于开启、关闭或挂起状态的虚拟机。
.. *要考虑的虚拟机存储*：选择为每个接入的虚拟机创建的数据存储是根据其当前使用的大小（推荐）还是其配置的大小来确定容量。
+
外部数据存储将使用 Amazon FSx for NetApp ONTAP 文件系统卷来实现。

.. *要考虑的虚拟机内存*：选择为每个已载入的虚拟机分配的内存大小是基于其当前已用大小（推荐）还是其已配置大小。


. 在 _VMware Cloud on AWS 部署配置_ 部分中，输入有关所需的 VMware Cloud on AWS 配置的详细信息。
+
.. *区域*：选择将部署 VM 和 Amazon FSx for NetApp ONTAP 文件系统的区域。
+
为了获得最佳性能和成本效益，这通常与部署现有 VMware Cloud on AWS SDDC 的地区相同。

.. *虚拟机估计性能要求*：此选项仅在使用 RVTools 时可用。迁移顾问虚拟机收集器从您的环境中捕获此信息。请提供要应用于将要部署的新虚拟机的以下每个虚拟机平均性能参数：
+
*** *每个虚拟机的平均 IOPS*：输入文件系统所需的 IOPS 数量。如果您不确定，可以为 Amazon FSx for ONTAP 文件系统使用默认值，即每 GiB SSD 存储 3 个 IOPS。例如，如果您部署 2,000 GiB 的容量，这将转换为 6,000 IOPS。我们建议您从较小的 IOPS 设置开始。在创建文件系统后，随着工作负载的迁移或部署，您可以增加已配置的 SSD IOPS。
*** *平均 I/O 块大小*：包含读取或写入操作的每个块的大小。默认大小为 4 KB。较大的块大小可能更适合大型顺序读写工作负载。较小的块大小可以为对稀疏文件或大文件执行小型随机写入的工作负载提供更好的性能。
*** *平均写入比率*：工作负载的写入操作所占的百分比。默认比率为 30% 写入和 70% 读取。




. 在 _VM 存储容量注意事项_ 部分，从几个存储选项中进行选择。
+
.. *平均数据缩减率*：从三个常见的数据缩减选择值中进行选择。选择“1:1 - 无缩减”、“1:1.25 - 缩减 20%”或“1:1.5 - 缩减 33%”。
.. *余量百分比*：输入添加到您的 FSx for ONTAP 文件系统容量中的容量增长百分比。
+
请注意，如果选择小于 20% 的数量，您将无法创建用于保护和长期备份的卷快照。



. 选择 *Next*，将显示“VMware cloud on AWS node configuration”页面。
+
此页面可让您使用估算的节省分析和推荐的节点类型来定义 VMware cloud on AWS 集群配置。您可以配置以下内容：

+
.. *vSAN 架构*：选择要使用 vSAN Express 存储架构（ESA）还是 vSAN 原始存储架构（OSA）架构。
.. *vSAN 容错*：选择虚拟机所需的容错级别。您可以选择推荐的“自动”，也可以从各种 RAID 级别中进行选择。
+
*** RAID-1（FTT 1）：由 2 个或更多磁盘上的一组数据的精确副本（或镜像）组成。
*** RAID-5（FTT 1）：由具有分布式奇偶校验的块级条带化组成——奇偶校验信息分布在 3 个或更多驱动器之间，并且可以承受单磁盘故障。
*** RAID-5（FTT 2）：由带有分布式奇偶校验的块级条带化组成 - 奇偶校验信息分布在 4 个或更多驱动器中，并且可以承受任意两个并发磁盘故障。
*** RAID-6（FTT 2）：通过添加另一个奇偶校验块来扩展 RAID 5；因此，它使用块级条带化，其中两个奇偶校验块分布在所有成员磁盘上。它需要 4 个或更多驱动器，并且可以承受任何两个并发磁盘故障。


.. *节点配置选择列表*：为节点选择 EC2 实例类型。


. 选择*下一步*，“选择虚拟机”页面将显示与您在上一页中提供的条件相匹配的虚拟机。
+
.. 在 _Selection criteria_ 部分中，为计划部署的虚拟机选择条件：
+
*** 基于成本和性能优化
*** 基于使用本地快照轻松恢复数据以用于恢复方案的功能
*** 基于两组标准：成本最低，同时仍然提供良好的恢复选项


.. 在_虚拟机_部分中，与您在前一页中提供的条件匹配的虚拟机已被选择（选中）。如果您想在此页面上载入/迁移更少或更多的虚拟机，请选择或取消选择虚拟机。
+
如果您进行任何更改，*推荐部署*部分将更新。请注意，通过选中标题行中的复选框，您可以选择此页面上的所有虚拟机。

.. 选择 *Next*。


. 在*数据存储部署计划*页面上，查看已建议迁移的虚拟机和数据存储总数。
+
.. 选择页面顶部列出的每个数据存储，查看将如何配置数据存储和虚拟机。
+
页面底部显示将为其配置此新 VM 和数据存储的源 VM（或多个 VM）。

.. 了解数据存储将如何部署后，选择*下一步*。


. 在*查看部署计划*页面上，查看您计划迁移的所有虚拟机的估计每月成本。
+
页面顶部描述了所有部署的 VM 和 FSx for ONTAP 文件系统的每月成本。您可以展开每个部分以查看“推荐的 Amazon FSx for ONTAP 文件系统配置”、“估算成本明细”、“卷配置”、“规模估算假设”和技术“免责声明”的详细信息。

. 对迁移计划感到满意后，有以下几种选择：
+
** 选择 *部署* 以部署 FSx for ONTAP 文件系统来支持您的虚拟机link:deploy-fsx-file-system.html["了解如何部署 FSx for ONTAP 文件系统"]。
** 选择 *下载计划 > 虚拟机部署* 以下载 .csv 格式的迁移计划，以便您可以使用它创建新的基于云的智能数据基础设施。
** 选择*下载计划 > 计划报告*以下载 .pdf 格式的迁移计划，以便分发计划以供审核。
** 选择 *导出计划* 以 .json 格式将迁移计划保存为模板。您可以稍后导入计划，以便在部署具有类似要求的系统时用作模板。
