= NetApp Workload Factory 中的数据保护类型
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
FSx for ONTAP 支持快照、NetApp 带有 AI 的自主勒索软件保护、复制和备份，以实现数据保护。我们建议您结合使用多种数据保护类型，为不可避免的情况做好准备，并保护您的数据。



[[types-of-data-protection]]
== 数据保护类型

为您的工作负载提供数据保护有助于确保您可以随时从任何数据丢失中恢复。在选择要使用的功能之前，请先了解数据保护的类型。

.Snapshot
快照在源卷内创建卷的只读时间点映像作为快照副本。您可以使用快照副本来恢复单个文件，或还原卷的全部内容。快照是所有备份方法的基础。在卷上创建的快照副本用于使复制的卷和备份文件与对源卷所做的更改保持同步。

.采用 AI 技术的 NetApp 自主勒索软件防护
带有 AI 的 NetApp 自治勒索软件防护（ARP/AI）使用 NAS（NFS/SMB）环境中的工作负载分析来检测并警告可能是勒索软件攻击的异常活动。当怀疑发生攻击时，除了计划快照提供的现有保护之外，ARP/AI 还会创建新的不可变快照。

.复制
复制在另一个 FSx for ONTAP 文件系统上创建数据的辅助副本，并不断更新辅助数据。您的数据会保持最新状态，并在您需要时随时可用，例如用于灾难恢复。

您可以选择在另一个 FSx for ONTAP 文件系统上创建复制卷，并在云中创建备份文件。或者，您可以选择仅创建复制卷或备份文件——这由您决定。

.备份
您可以将数据备份到云中，以进行保护和长期保留。如有必要，您可以将备份中的卷、文件夹或单个文件还原到相同或不同的工作文件系统中。

[[best-practices-for-protecting-your-workload-data]]
== 保护工作负载数据的最佳实践

FSx for ONTAP 提供多种数据保护选项，可结合使用以实现您选择的恢复点和时间目标。为了获得最佳保护，我们建议您同时使用卷快照和卷备份。

恢复点目标 (RPO) 描述了数据最新副本的保证时效，这取决于副本的创建频率。恢复时间目标 (RTO) 定义了恢复数据所需的时间。



[[protect-your-workload-data-with-snapshots]]
== 使用快照保护您的工作负载数据

快照是按计划创建的卷的虚拟时间点版本。您可以使用标准文件系统命令访问快照。快照提供的 RPO 最短仅为一小时。RTO 取决于要恢复的数据量，并且主要受卷吞吐量限制。快照还允许用户恢复特定文件和目录，从而进一步降低 RTO。快照仅会为对卷所做的更改消耗额外的卷空间。



[[protect-your-workload-data-with-netapp-autonomous-ransomware-protection-with-ai]]
== 使用带有 AI 的 NetApp 自主勒索软件防护来保护您的工作负载数据

如果防病毒软件未能检测到入侵，带有 AI 的 NetApp 自主勒索软件防护（ARP/AI）可作为重要的额外防御层。设置 ARP/AI 策略可为所有存储 VM 以及所有现有和新创建的卷启用该策略。启用后，ARP/AI 将检测并保护所有卷和存储 VM。如果文件扩展名被标记为异常，则应评估警报。



[[protect-your-workload-data-with-volume-replication]]
== 使用卷复制保护您的工作负载数据

卷复制会在不同区域创建卷最新数据的副本，包括其所有快照。如果您无法承受从卷备份执行完整卷还原操作长达数小时的 RTO，请考虑执行卷复制。虽然卷复制可确保在不同区域提供最新数据供您使用，但您需要调整客户端以使用其他区域中的卷。



[[protect-your-workload-data-with-backups]]
== 使用备份保护您的工作负载数据

卷备份提供卷的独立时间点副本。它们可用于存储旧备份并提供必要的第二个数据副本。每日、每周和每月备份计划允许从一天开始的 RPO。卷备份只能作为一个整体还原。从备份（RTO）创建卷可能需要数小时到数天，具体取决于备份的大小。



[[recommendations-for-protecting-your-workload-data]]
== 有关保护工作负载数据的建议

请考虑以下保护工作负载数据的建议。

* 使用卷复制进行灾难恢复：如果您的应用程序需要较低的 RTO，请考虑使用卷复制将数据复制到另一个区域。
* 将卷备份与快照结合使用：同时使用这两个功能可确保您能够从快照中还原文件，并在发生卷丢失时使用备份执行完全还原。
* 定义卷备份策略：确保备份策略满足公司对备份期限和频率的要求。我们建议为每个卷保留至少两个每日备份。
* 定义快照计划：较旧的快照不太可能用于还原数据。我们建议您定义一个快照计划，综合考虑保留较旧快照的递减收益与额外快照容量成本之间的关系。
* 为您的文件系统或单个卷启用 ARP/AI 策略，以添加额外的保护层，保护您的数据免受勒索软件攻击。
