= 了解 NetApp Console 中的自定义规则
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
自定义规则可让您在架构完善的仪表板中设置、检查和执行您自己的架构标准以及 NetApp 最佳实践。



[[overview]]
== 概述

规则生成器允许您使用简单语言创建自定义规则。这些规则会在您的所有资源中进行检查。自定义规则可帮助您执行默认规则可能无法涵盖的组织标准、风险限制和运营要求。


NOTE: 如果您的账号管理员已关闭 AI 功能，您将无法创建新规则或编辑现有规则。任何已计划的规则都将继续运行。link:../admin/manage-genai-features.html.["了解如何管理 AI 功能"^]。



[[how-custom-rules-work]]
== 自定义规则的工作原理

自定义规则使用 AI 将自然语言指令转化为清晰、结构化的规则。AI 会翻译您的请求，提供规则建议，解释其如何理解您的指令，并在保存或计划规则之前请求批准。此流程有助于确保：

* 规则已明确定义并检查错误
* 未执行任何自定义代码
* 在批准规则之前，您可以准确查看将要评估的内容
* 每个自定义规则包括要评估的资源类型、条件逻辑、严重性、评估计划和补救指南。




[[before-you-begin]]
== 开始之前

在创建和运行自定义规则之前，请确保具备以下条件：

AWS 凭据:: 对 AWS 环境的只读访问。自定义规则需要只读权限作为安全边界。link:https://docs.netapp.com/us-en/workload-setup-admin/add-credentials.html["将 AWS 凭据添加到 Workload Factory"^]。
ONTAP 凭据:: 具有只读权限的 FSx 查看器用户。如果尚不存在，Workload Factory 会在每个 FSx for ONTAP 文件系统上创建一个只读用户，以便其执行评估。
链接或代理:: 仅适用于必须直接连接到 ONTAP 以检查 AWS API 无法访问的设置的规则link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["通过链接连接到 FSx for ONTAP 文件系统"^]。




[[limitations]]
== 限制

* 规则无法自动解决问题。您必须使用提供的指南自行更正不合规的资源。
* 每个规则只检查一种类型的资源，但它可以应用于各种资源。例如，一个规则可以评估多个区域、所有区域或多个帐户的卷。要评估不同的资源类型，请创建单独的规则。
* 规则最多每小时运行一次，以防止过度扫描。
* 规则只能读取您的环境，无法进行更改。
* 您可以稍后从规则目录中更新这些设置。




[[rule-lifecycle]]
== 规则生命周期

自定义规则经历以下状态：

进行中:: 创建或检查规则。
无法创建:: 无法创建规则。您可以重新打开规则并在聊天中继续编辑。
初稿:: 已保存但尚未计划。
已验证草稿:: 已通过验证，可以保存或计划。
编辑:: 更新现有规则的草稿副本。在保存更改之前，当前计划的规则将继续运行。
已计划:: 活动并按照定义的时间表运行。
已禁用:: 已暂停但未删除。可以重新启用。
已删除:: 已永久删除。




[[custom-rule-examples]]
== 自定义规则示例

生产卷保护:: "所有带有标记 'Prod' 的卷必须安装快照策略"
+
--
此规则会自动创建快照，以根据公司要求保护生产卷。

--
归档卷分层:: "所有带有标记 'Archive' 的卷都应将分层策略设置为 'All'"
+
--
此规则通过自动将存档数据移动到更便宜的存储来降低成本。

--
文件系统命名标准:: "所有文件系统必须遵循命名约定 'fsx-{environment}-{application}'"
+
--
此规则验证文件系统是否遵循组织命名约定，以便于管理和成本分配。

--
