=== Workload Factory 管理增强功能



==== 检查和刷新自定义仪表板数据

现在，您可以查看上次更新自定义控制面板指标的时间，并手动刷新这些指标。将鼠标悬停在*刷新数据*上以查看上次更新的日期和时间。

选择*刷新数据*以开始新的扫描。横幅将确认扫描已开始，并且该按钮将被禁用，直到扫描完成。

有新数据可用时，请在通知横幅中选择*立即加载*以更新控制面板。

*刷新数据*和*立即加载*均会在 Tracker 中创建数据收集事件。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/manage-custom-dashboards-fsx.html#refresh-dashboard-data["了解如何刷新自定义仪表板数据"]



==== 指定自定义仪表板的区域

如果您的请求未包含区域，自定义控制面板现在会要求您选择一个或多个区域。控制面板数据仅限于您选择的区域。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/create-custom-dashboard-fsx.html["了解如何创建自定义仪表板"]



==== FSx for ONTAP 链接创建的 IAM 策略

用于创建链接的 CloudFormation 模板和 Terraform 代码现在使用 IAM 策略而不是内联 Lambda 权限。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-storage/create-link.html["了解如何创建链接"]



==== 审核和跟踪 AI 代理操作

您现在可以使用 Tracker 查看 AI 代理设置的更改，并在读/写模式下查看每个审批请求，包括代理的问题和用户的答案。

通过 Workload Factory API 进行的资源更改由执行该操作的 Workload Factory 服务记录。

link:https://docs.netapp.com/us-en/data-services-workloads/admin/learn-agent.html["了解审核和跟踪代理操作的相关信息"]

==== 启动程序组图增强功能

在“管理客户端访问权限”页面上显示块设备启动器组的图表现在包括主机的更多详细信息。当您将鼠标悬停在图表中的主机上时，将显示主机详细信息，包括主机名、实例 ID、工作负载类型、区域和 iSCSI 限定名称（IQN）。



==== 针对架构完善的问题的电子邮件增强功能

新的电子邮件设计为 Workload Factory 检测到的配置问题提供了更多详细信息和上下文。该电子邮件包括已分析的资源数量、存在警告或严重问题的资源数量，以及这些问题是什么。该电子邮件还链接到 FSx for ONTAP 架构完善的控制面板，以便您可以立即解决问题。



==== 精心设计的仪表板增强功能



===== 支持选定的配置检查

您可以对选定配置手动运行分析，以便仅分析您感兴趣的配置并减少等待时间。



===== 精心设计的分析中的新建议

Workload Factory 现在在 FSx for ONTAP 文件系统的良好架构分析中包含以下配置：

对于存储工作负载：

* *将主机连接到故障转移节点*：检查主机是否连接到主动-被动 FSx for ONTAP 文件系统中的故障转移节点，以确保可靠性。
* *将主机连接到首选节点*：检查主机是否使用首选节点连接到其块设备，以提高性能效率。
* *ARP/AI 多设备检测差距*：当卷仅连接了一个块设备时，ARP/AI 可提供全面的保护覆盖。如果卷连接了多个块设备，Workload Factory 会将这些块设备移动到新卷，以便每个卷只有一个块设备。
* *克隆清理*：检查是否有任何超过 30 天的卷克隆可以删除，以优化存储使用并降低成本。
* *将 igroup OS 与主机匹配*：检查启动器组（igroup）的操作系统是否与主机的操作系统匹配，以防止 I/O 或性能问题。


对于 Kubernetes 工作负载：

* *QoS 配置*：检查 Kubernetes 持久卷是否受到 ONTAP QoS 策略的保护，以提高性能效率。
* *专用 Kubernetes 存储虚拟机*：检查文件系统是否正在为 Kubernetes 工作负载使用专用存储虚拟机，以提高隔离度并简化存储管理。
* *专用 Kubernetes 导出策略*：检查每个 Kubernetes 持久卷是否具有仅允许从集群的工作节点访问的专用导出策略。
* *Kubernetes iSCSI 后端的双向 CHAP*：检查 Trident iSCSI 后端是否启用了双向 CHAP 身份验证以确保安全。
* *在应用程序存储 VM 上禁用 `showmount`*：检查是否在应用程序存储 VM 上禁用了 `showmount`，以防止客户端列出其无法访问的导出。


对于数据库工作负载：

* *SAP HANA 快照策略*：检查 SAP HANA 卷的快照策略是否设置为“无”，以降低存储成本并提高活动数据库数据的性能。
* *MySQL 快照策略*：检查 MySQL 卷的快照策略是否设置为“None”，以降低存储成本并提高活动数据库数据的性能。
* *PostgreSQL 快照策略*：检查 PostgreSQL 卷的快照策略是否设置为“None”，以降低存储成本并提高活动数据库数据的性能。




===== 配置的当前值和建议值

您可以在架构完善的仪表板中查看某些未优化配置的当前值和推荐值。这可让您在进行修复之前了解推荐值。

* 冷数据分层
* Snapshot 策略
* 固态硬盘容量余量




==== 成本改进



===== 成本预测和见解

现在，您可以使用成本预测功能预测 FSx for ONTAP 文件系统的成本。这有助于您规划预算并有效优化资源。您还可以查看有关成本和使用模式的见解，以确定成本优化的机会。



===== AWS 成本和使用情况报告（CUR）

Workload Factory 现在使用 AWS Cost and Usage Reports（CUR）而不是 AWS Cost Explorer 来提供交付给客户拥有的 S3 存储桶的详细计费记录。CUR 提供了更好的成本粒度，并作为高级 FinOps、内部计费和成本分配用例的基础。



==== Storage VM 迁移改进

Workload Factory 在用户界面中为迁移存储虚拟机提供增强的指导。这包括分步说明以及在将迁移提交到生产环境之前进行测试运行。

link:fsx-storage/create-replication.html["详细了解存储虚拟机迁移"]



==== 复制滞后电子邮件通知改进

当发生大量相关复制延迟事件时，Workload Factory 会自动将其合并为一封电子邮件通知，以免您收到过多通知。



==== 自动容量管理增强

现在，您可以在要求 Workload Factory 自动管理您的容量之前，打开自动容量管理通知以试用此功能。当您的文件系统容量不足时，您将收到通知。



==== 精心设计的仪表板中包含的数据库配置

精心设计的仪表板现在包含针对您的数据库配置的建议，使您能够根据最佳实践评估和优化设置。仪表板中包含的首批配置包括：

* 冷数据分层
* 存储效率
* Snapshot 策略
* 固态硬盘容量余量
* 块设备空间管理
* OS 类型
* 将块设备操作系统类型与主机匹配
* 非活动的数据块设备（LUN）
* 数据文件（.mdf）放置
* 日志文件（.ldf）放置
* 多路径 I/O 状态
* 多路径 I/O 超时
* 集群仲裁
* 计算资源合理调整


在 Workload Factory 控制台中选择主菜单，然后选择 *Well-architected* 以查找架构完善的仪表板。

image:well-architected-menu-option.png["Workload Factory 控制台中的架构完善菜单选项"]



==== 吞吐量决策点

您现在可以查看客户端吞吐量建议和自动化决策点。将鼠标悬停在决策点上可查看详细信息，例如当前和推荐的 SKU 或时间窗口中的违规指标（%）。



[[workload-factory-for-vmware-enhancements]]
=== Workload Factory for VMware 增强功能

这些增强功能涵盖了适用于 VMware 迁移的 EVS TCO 计算器。



==== 在 EVS TCO 计算器中支持 i7i.metal-24xl 和 i7i.metal-48xl 实例

EVS TCO 计算器现在支持 AWS i7i.metal-24xl 和 i7i.metal-48xl EC2 实例作为集群主机。与 i4i.metal 配置相比，i7i.metal-24xl 实例将计算的 EVS 起始成本降低了约 33%，将 vSAN 存储的 EVS 起始成本降低了 25%。

计算器比较所有实例类型并自动选择成本最低的选项。新的对比部分会并排显示 EVS 主机配置，以便更轻松地根据您的需求选择最佳设置。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-vmware/calculate-evs-savings.html["计算 EVS 的预计节省金额"]



[[workload-factory-for-eda-enhancements]]
=== Workload Factory for EDA 增强功能

这些增强功能涵盖了延迟分析中的卷详细信息、文件系统压力检查、吞吐量决策点以及再次运行延迟分析。



==== 在延迟分析期间查看卷详细信息

在分析延迟事件时，您可以在 Workload Factory 中查看更多卷详细信息，以便了解卷的配置方式。详细延迟分析页面显示 *卷类型*（RW 或 DP）和 *卷样式*（FlexVol 或 FlexGroup）。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-analyze-latency-trends.html["了解如何分析延迟趋势"]



==== 检查延迟事件的文件系统压力

在 Workload Factory 中，您可以检查延迟事件发生时文件系统压力是否影响了性能，以便您决定是否调查文件系统。对于出现延迟警报的卷，您可以查看事件发生前 40 分钟的 CloudWatch 数据，并打开文件系统以进行进一步调查。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/learn-latency-monitoring.html#file-system-pressure["了解文件系统压力检查"]



==== 审查 EDA 的吞吐量决策点

您可以在 EDA 概述仪表板上查看客户端吞吐量决策点，以便查看 Workload Factory 何时建议或应用了吞吐量更改。将鼠标悬停在决策点上可查看详细信息，例如当前和推荐的 SKU 或时间窗口中的违规指标。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-use-overview-dashboard.html#analyze-capacity-and-throughput-trends-and-decision-points["了解如何查看吞吐量决策点"]



==== 再次运行延迟分析

您可以在 Workload Factory 中再次对卷运行延迟分析，以便在调查或进行更改后刷新结果。选择 *再次运行分析* 以开始新的分析并更新结果。

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-eda/task-analyze-latency-issues.html["了解如何分析延迟问题"]



[[google-cloud-netapp-volumes-enhancements]]
=== Google Cloud NetApp Volumes 增强功能



==== 查看 Google Cloud NetApp Volumes 存储池

您现在可以在 NetApp Workload Factory 中查看您的 Google Cloud NetApp Volumes 存储池。按项目、凭据和区域进行筛选，并选择存储池的名称以查看其完整详细信息，包括可用区、副本可用区、吞吐量、描述和标签。



[[oci-netapp-storage-service-enhancements]]
=== OCI NetApp 存储服务增强功能



==== 针对 OCI NSS 系统的架构完善的分析

NetApp Workload Factory 包括针对 OCI NSS 系统的架构完善的评估。该评估提供了见解、建议和修复措施，以帮助您实现卓越运营。

配置评估可用于 OCI Well-Architected Framework 的以下支柱：

* 可靠性：文件对象容量、快照策略和 SSD 容量空间
* 卓越运营：主机可见容量报告和卷容量余量
* 成本优化：冷数据分层、快照清理和存储效率


详细了解link:https://docs.netapp.com/us-en/data-services-workloads/oci/add-credentials-oci.html["针对 OCI NSS 系统的架构完善分析"]和link:https://docs.netapp.com/us-en/data-services-workloads/oci/improve-configurations.html["实施精心设计的配置"]。
